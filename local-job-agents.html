02

The split that matters

Three tiers, and the tier a project sits in tells you more than its feature list does. A tool in tier A without tier C is a machine that sends your CV to whatever it finds.

Tier A — presses Submit

End-to-end appliers

Discovery, scoring, tailoring and a browser that fills and sends the real form. Every one of them is one bad config away from sending something you did not read.

  • AIHawk
  • ApplyPilot (+ two active forks)
  • scout
  • agentic-job-applier — gated
  • claude-job-auto-apply
Tier B — fills, never sends

Assistants

The form is completed for you, including the free-text screening questions. You read it, fix the one answer it got wrong, and click. Slower per application, far safer per week.

  • JobNavigator
  • MR.Jobs — dry-run default
  • AutoApply — submit still unimplemented
Tier C — decides

Judgement layers

The half of the problem nobody automates: is this posting real, is it still open, is it worth your evening, and what does a recruiter at this company actually want to read.

  • career-ops
  • ApplyPack
  • JobSpy — raw discovery only

“Every project in this list that is worth using ships a dry-run or an approval gate. The ones that do not are the ones with five stars and a CAPTCHA solver.”

03

The India problem

The single most useful thing I learned, and it does not appear in any of the READMEs.

Geographic
mismatch

Almost every auto-submit path is built for American and European hiring.

The supported ATS lists read the same across projects: Greenhouse, Lever, Workday, Ashby, iCIMS, Taleo. Indian employers hire overwhelmingly through Naukri and LinkedIn — and LinkedIn Easy Apply is deliberately unsupported by most of these tools, because it is the path that gets accounts banned fastest.

The one component with native Naukri support is JobSpy, which parses Naukri’s own JSON API and converts “12–16 Lacs P.A.” into real numbers. It is a scraper, not an applier. So for a search based in India, expect the submit half of tier A to earn its keep mainly on multinationals hiring into India — and expect the discovery and tailoring half to do the real work everywhere else.

04

How to choose

Pick by the outcome you want, not by the feature table.

If you want it to actually submit

AIHawk or ApplyPilot

AIHawk for the largest community and the newest rewrite; ApplyPilot for a cleaner staged pipeline you can run one stage at a time, with a real dry-run. Run --dry-run at least once before anything leaves your machine.

If you want a console, not a black box

JobNavigator or MR.Jobs

Both are Docker, both keep state locally, both autofill rather than submit. JobNavigator is the more finished product; MR.Jobs has the better safety defaults — dry-run on, 25/day cap, headed browser.

If you want better decisions, not more applications

career-ops

It scores the JD against your CV, checks the posting is still real, drafts the documents, and leaves the Submit click to you. It also happens to be the one that runs on Antigravity CLI today.

If you want zero API spend

scout, ApplyPack, or career-ops

scout and ApplyPack both run on free Gemini tiers or a local Ollama model. career-ops costs nothing extra if you already pay for a coding CLI — it borrows the subscription you have.

If you want to build your own

JobSpy + Playwright + a gate

That is what most of this table already is, under a different name. Take JobSpy for discovery, Playwright for the form, and put a human approval step before submit — the projects that skipped that step are the ones with the most caveats.

If you are applying at volume, anywhere

Read the terms first

Mass auto-apply breaches the terms of several job boards and produces applications recruiters can spot. “1,000 applications in two days” is a spray-and-pray story, not a success metric. Cap the volume, and read every CV the tool generates.

Method & sources

How this was assembled, and what would change the conclusions.

How I checked

  • Primary sources first. Each project’s own README and docs, read at the repository, not summaries of them.
  • Submission behaviour taken from each project’s own statement of what it will and will not do — this is the column most likely to be misreported elsewhere.
  • Star counts and licence read in early November 2026 and rounded; they move daily.
  • Nothing was installed or run. Every claim here is documentation, not hands-on testing — verify against your own machine before trusting it.

What would change this

  • An Indian ATS story. If a project adds Naukri or foundit submission, the geographic caveat shrinks and tier A becomes useful here.
  • AIHawk’s rewrite is three days old. Its reliability at scale is unproven; the star count is inherited from the 2024 LinkedIn-only tool.
  • Small projects rot fast. Anything under roughly 50 stars in this table — MR.Jobs, agentic-job-applier, claude-job-auto-apply, scout — may be unmaintained by the time you read this.
  • Board terms change. Automation that works today can be blocked next quarter; that risk sits with you, not the project.
